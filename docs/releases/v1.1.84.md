# v1.1.84 - updater stale-file recovery

This maintenance release fixes production updates that can fail after a release removes or renames source files.

## Self updater

- Production source synchronization now uses `rsync --delete-delay` so release-controlled files removed from GitHub are also removed from the deployed source tree.
- Runtime state remains protected from pruning:
  - `.env`
  - `node_modules`
  - `.next`
  - `.next-update`
  - `tmp`
  - `public/.htaccess`
  - `public/.well-known`
  - `public/uploads`
- Local Media Library uploads therefore survive normal self updates.

## v1.1.83 recovery bridge

v1.1.83 removed the old `PersonalWikiEditor.tsx`, but older updater versions copied new files without deleting obsolete ones. A stale copy could remain on N0C and fail TypeScript checks even though the file no longer existed on GitHub.

v1.1.84 includes a temporary compatibility shim at the old path. This allows an installation still running the pre-v1.1.84 updater to overwrite the stale invalid file and successfully complete its first v1.1.84 build. Once v1.1.84 is installed, future removed files are pruned automatically by the updated updater.

## N0C / Next.js build cleanup

- Removed `experimental.useWasmBinary`, which Next.js 16 ignores on supported `linux/x64` hosts and reports as a warning.
- Kept the existing low-memory webpack/N0C build tuning.
- Removed the custom `Cache-Control` override for `/_next/static/*`; Next.js already manages immutable static chunk caching and warns against overriding it.

## Release

- Version: `1.1.84`
- No Prisma migration.
- No dependency changes.
