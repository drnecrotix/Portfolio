# v1.1.81 - Resilient GitHub Lab proof

## Fixed

- The Lab no longer stays on `Portfolio fallback` only because a GitHub token is missing or cannot access the GraphQL repository connection.
- GitHub proof now resolves the profile username from API Integrations, `GITHUB_USERNAME`, or the GitHub URL configured in Site Settings.
- The preferred proof path uses GitHub GraphQL with the configured token and the explicit public profile username instead of relying on `viewer.repositories`.
- If GraphQL is unavailable, restricted by token scopes, or returns no usable proof data, the endpoint automatically falls back to GitHub's public REST repository API.
- Public REST fallback still provides real GitHub-backed proof from repository primary languages and topics.

## API Integrations

- GitHub connection testing now verifies the same data path used by The Lab instead of only checking `GET /user`.
- A successful test reports whether Lab proof is healthy through GraphQL or through the public REST fallback.
- GitHub username can be stored as `github.username`; public profile configuration can also be inferred from Site Settings social links.

## Mobile polish

- The Lab hero now uses a dedicated mobile/tablet layout below 1024px.
- The Spline robot and floating technology icons are not mounted on mobile/tablet, reducing visual clutter and unnecessary 3D runtime work.
- Mobile hero spacing, title, description and CTA are centered and compact while the desktop 3D composition remains unchanged.
- Blog article Like, Views and Share controls stay in one horizontal non-wrapping row on mobile.
- `A note from the journal` is hidden on small screens to preserve room for the action controls.
- The language switch moves to its own row on mobile when multiple locales are available.

## Deployment

- Version bumped to `1.1.81`.
- Adds optional `GITHUB_USERNAME` environment fallback.
- No Prisma migration.
- No dependency changes.
- Existing v1.1.80 API Integration credentials remain compatible.
