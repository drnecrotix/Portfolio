# Portfolio v1.3.5

## Service Monitoring scheduler setup

- Removes the requirement to define a separate `MONITORING_CRON_SECRET` before recurring monitoring can be scheduled.
- Keeps `MONITORING_CRON_SECRET` as an optional backward-compatible dedicated scheduler credential when explicitly configured.
- When the dedicated value is absent, derives a scoped HMAC scheduler token from the first available protected server credential: `INTEGRATION_CREDENTIALS_SECRET`, `AI_CREDENTIALS_SECRET`, or `AUTH_SECRET`.
- The derived token does not expose or reuse the underlying Auth/integration secret directly.
- Admin > Service Monitoring now reports `scheduler ready`, shows only a masked token preview and provides a one-click copy of the complete PlanetHoster cron command.
- Rotating the underlying server credential rotates the derived scheduler token; Admin warns that the cron command must then be copied again.
- The internal scheduler endpoint accepts the same bearer-authenticated POST flow and continues to run at most three due plans sequentially per invocation.
- Manual monitoring runs and the weekly/monthly monitoring engine are unchanged.

## Documentation

- Updates `.env.example` to mark `MONITORING_CRON_SECRET` as optional.
- Updates the production monitoring guide with the derived-token flow and the Admin-provided cron command.

This release changes scheduler authentication/setup only. It does not add a database migration or change service-monitoring plan data.
