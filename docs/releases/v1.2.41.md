# Portfolio v1.2.41

## Unified comments engine

- Reworks comments into one shared engine for Blog publications, Gallery works and Store products.
- Preserves existing Blog comment IDs, replies and moderation history while adding generic source metadata.
- Adds clear source metadata to every comment: `BLOG`, `GALLERY` or `PRODUCT`, plus source title and public path.
- Adds the same editorial discussion UI to Blog, Gallery and Product detail pages.
- Keeps guest commenting only: public display name, optional private email and no account requirement.
- Removes social-style UI expectations such as avatars, badges and reaction emoji from the new comments interface.
- Allows replies to replies while limiting visual indentation so mobile threads remain readable.
- Adds comment permalinks, inline replies and sorting by newest, oldest or most replied.

## Spam handling

- Any submitted comment containing a public URL or domain is stored directly as `SPAM` and never shown publicly.
- Spam is retained for up to 7 days so false positives can be restored, then deleted opportunistically by the comments engine/admin workflow.
- Existing honeypot and human-verification checks remain active.

## Admin moderation

- Rebuilds `/admin/comments` as one moderation inbox for Blog, Gallery and Products.
- Adds source filters and clear source labels/title links for every comment, so mixed moderation views always show where a comment belongs.
- Adds Approved and Spam views with spam-expiry information.
- Adds multi-select moderation with bulk Approve, Mark spam and Delete actions.
- Keeps direct links from moderation rows to the related publication, gallery work or product.

## Migration

- Adds `CommentSource` with `BLOG`, `GALLERY` and `PRODUCT` values.
- Extends the existing `BlogComment` table rather than creating three separate comment stores.
- Makes `postId` optional for Gallery and Product comments while preserving the Blog relation.
- Existing Blog rows are backfilled with source slug, title and path metadata.
- Parent deletion now uses `SET NULL` so hard deletion does not cascade through an entire reply chain.
