# Portfolio v1.2.42

## Client bundle hardening

- Explicitly disables production browser source maps.
- Removes `unsafe-eval` from the production Content Security Policy while keeping it available in development.
- Adds `X-DNS-Prefetch-Control: off` to the global security headers.
- Marks the shared Prisma runtime as `server-only` so accidental imports from Client Components fail at build time.
- Marks social metadata URL resolution as `server-only` and prefers the server-side `SITE_URL` / `AUTH_URL` configuration before the backwards-compatible `NEXT_PUBLIC_SITE_URL` fallback.

## Client/server boundary audit

- Adds `npm run security:client-boundaries`.
- Scans every `use client` source file before the production build.
- Fails if a Client Component imports Prisma, auth, credential vaults, payment integrations, storage runtime or other explicitly server-only modules.
- Fails if a Client Component references private environment variables or dynamically accesses `process.env`.
- Fails if a Client Component imports Node.js built-ins directly.

## Bundle leakage audit

- Adds `npm run security:client-bundle`.
- Fails CI if browser `.map` files are emitted.
- Fails CI if browser assets contain `sourceMappingURL` references.
- Scans browser assets for configured sensitive environment values such as `AUTH_SECRET`, `DATABASE_URL`, assistant/integration credential secrets and payment/storage secrets without printing the secret values.
- Runs the audit after the standard build, the N0C compatibility build and the staged updater build.

## Production runtime

- The custom Node/N0C server rejects `.map` requests with `404` in production so stale source-map artifacts cannot be served accidentally.
- `SITE_URL` can now be used as the preferred server-only canonical site URL while existing `AUTH_URL` and `NEXT_PUBLIC_SITE_URL` deployments remain compatible.
- Production preflight accepts `SITE_URL`, `AUTH_URL` or the legacy `NEXT_PUBLIC_SITE_URL` and still requires HTTPS in production.

## Credential handling review

- Confirmed that the API Integrations admin page passes only configured/source state to the Client Component rather than decrypted API key values.
- Existing assistant/integration credential vault modules remain `server-only` and encrypted at rest.

## Scope

- This release does not attempt to encrypt or obfuscate browser JavaScript. Code that must execute in the browser remains inspectable after minification.
- The protection strategy is to keep sensitive logic and secrets server-side, prevent source reconstruction through source maps and continuously audit production browser bundles for leakage.
- No Prisma migration or content schema change is included.
