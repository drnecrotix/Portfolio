# Portfolio v1.2.25

## Retained audience activity

- Adds retained public-page activity to `Audience & traffic` with time, page pathname, country, coarse city, broad device class and short-lived IP context.
- Removes query strings and URL fragments before storing activity so tokens and arbitrary parameters are not retained.
- Shows the latest 150 activity rows in a bounded, scrollable Admin table while aggregate totals continue to cover the full selected period.
- Retains page/location/device activity for up to about 31 days.
- Clears raw IP values from retained page-activity rows after about 24 hours while preserving the non-IP history.

## Cities and IP location fallback

- Keeps hosting/CDN country and city headers as the preferred location source.
- Adds a server-side `ipwho.is` fallback when the hosting/CDN does not provide a city header and a public client IP is available.
- Stores only country code and coarse city from the fallback response.
- Does not retain latitude, longitude or precise coordinates.
- Expands the Cities view from live-only data to retained city page activity plus current online visitors.

## Device analytics

- Makes `Visits by device` more compact and table-like.
- Adds recent unique IP context for each device class.
- Limits displayed IPs and uses the short IP-retention window so the block cannot grow without bounds.

## Performance and retention

- Heartbeats continue to update live presence without creating duplicate page-history rows.
- Page activity is written only on real navigation events.
- Adds indexed `TrafficPageEvent` storage for time, session, country, device and path queries.
- Limits the Admin activity payload to the latest 150 rows for responsive rendering.

## Privacy and documentation

- Updates Privacy & GDPR and Cookie Policy for retained page activity, city fallback and short-lived raw IP context.
- Makes it explicit that query strings, URL fragments and precise coordinates are not stored.

## Compatibility

- Adds Prisma migration `20260906154500_traffic_page_activity`.
- The migration is additive and does not rewrite existing traffic aggregates or live sessions.
