# v1.2.18

## Store mobile viewport fix

- Keeps the public `/store` catalog inside the visible mobile viewport.
- Makes search, sort controls, product cards, badges and long product text mobile-safe.
- Keeps `/store/[slug]` product pages from creating horizontal page overflow.
- Makes purchase controls and policy consent text wrap safely on narrow screens.
- Changes the cart popover to a viewport-contained mobile panel so it cannot extend off-screen when the cart icon is not at the far-right edge.
- Keeps category navigation horizontally scrollable inside its own rail instead of widening the document.

## Site-wide responsive regression checks

- Expands Playwright smoke coverage across the main public portfolio, Gallery, Journey, Lab, Wiki, Achievements, Resume, Store and legal pages.
- Removes the old broad mobile horizontal-overflow tolerance and requires every audited public document to stay within 2 px of its viewport.
- Adds a 360 px small-mobile test profile in addition to the existing Pixel 7 and desktop profiles.
- Adds a live production audit that discovers public HTML routes from the sitemap and same-origin links, then checks desktop, mobile and small-mobile layouts, HTTP failures, browser errors and broken loaded images.
- Downloadable assets such as PDF/ZIP/media files are excluded from HTML navigation checks so intentional downloads are not reported as broken pages.

## Admin reliability and security

- Replaces the decorative hard-coded Dashboard health state with a real database-backed health result. If the database query fails, the control center stays renderable and reports `Degraded` / `Unavailable` instead of claiming that everything is healthy.
- Reduces Dashboard traffic refreshes from every 5 seconds to every 15 seconds.
- Keeps `/api/admin/traffic` read-only. Traffic retention cleanup remains on the page-view ingestion path instead of running database delete queries on every open Dashboard refresh.
- Adds server-side admin login throttling using bounded, hashed IP and email buckets while keeping authentication errors generic.
- Revalidates the current admin user against the database on protected auth checks, so account deactivation takes effect immediately and role changes no longer wait for an old JWT to expire.

No database migration is required.
