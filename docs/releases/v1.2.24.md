# Portfolio v1.2.24

## Experiment measurement integrity

- Rebuilds A/B measurement around unique browser-session experiment events instead of relying on raw repeatable counters for statistical decisions.
- Adds a random HTTP-only `necrotix_experiment_session` cookie whose value is hashed server-side before it is used for experiment-event deduplication.
- Records at most one copy of a given experiment event per experiment and browser session.
- Automatically records the matching exposure when an outcome arrives before an exposure event, so denominators remain internally consistent.
- Keeps the first measured variant sticky for the session and cross-checks the existing variant-assignment cookie.
- Ignores experiment telemetry for likely bots and when the browser sends Do Not Track.
- Keeps legacy aggregate `ExperimentMetric` counters for compatibility, but v1.2.24 statistical decisions use only the new clean session-level sample.

## Statistical analysis

- Adds 95% Wilson confidence intervals for per-variant conversion rates.
- Adds a two-sided frequentist two-proportion test for the primary metric.
- Shows absolute percentage-point delta, relative lift, p-value and a 95% confidence interval for the A/B difference.
- Adds Sample Ratio Mismatch checks against each experiment's configured traffic allocation.
- Treats SRM as a data-quality warning before interpreting a potential winner.
- Adds explicit minimum evaluation samples per variant so small early samples are labelled as collecting data instead of being over-interpreted.
- Adds decision states for collecting, data-quality issue, primary metric favoring A, primary metric favoring B and inconclusive results.
- Adds secondary metrics as guardrails rather than declaring an experiment winner from one number alone.
- Adds a 14-day exposure-velocity view for each experiment.

## A/B Test dashboard

- Redesigns the Experiments view around decisions and data quality instead of raw event totals.
- Adds top-level Running, Clean exposures, Decision ready and Data quality summaries.
- Shows sample progress, observed A/B split, SRM probability, statistical evidence and the current decision state for every experiment.
- Compares control and treatment in dedicated cards with conversion rates, unique exposed sessions and confidence intervals.
- Adds a compact B-vs-A panel with absolute delta, relative lift, delta confidence interval and p-value.
- Adds a secondary-metrics table for guardrail outcomes.
- Keeps Audience & traffic as a separate focused view.

## Audience & traffic history

- Adds retained public-page activity with page pathname, country, coarse city, broad device class and hashed traffic-session reference.
- Removes query strings and URL fragments before storing page activity so tracking tokens and arbitrary parameters are not retained.
- Shows the latest 150 page-activity rows in a bounded, scrollable Admin table while aggregate analytics still cover the full selected period.
- Adds a compact `Time / Page / Location / Device / IP` activity view.
- Expands the Cities tab from live-only data into retained city page activity plus current online visitors.
- Adds a server-side country/city fallback through `ipwho.is` when the hosting/CDN does not provide a city header.
- Stores only the country code and coarse city label from the location response; latitude, longitude and precise coordinates are not retained.
- Keeps raw IP context available to authorised Admin analytics for about 24 hours, then clears the IP while retaining non-IP page activity for up to about 31 days.
- Makes `Visits by device` more compact and adds recent unique IP context per device without turning the panel into an unbounded IP list.
- Keeps live visitors and current pages driven by the existing heartbeat system, so heartbeats do not create duplicate page-history rows.

## Hero micro-navigation experiment

- Fixes `hero-micro-cta`, which was previously defined but not actually rendered or measured on the homepage.
- Variant B now adds restrained `View projects` and `Explore gallery` text navigation below the hero without turning the hero into a conventional CTA block.
- Measures comparable project discovery, projects-section reach and blog activity for both A and B variants.

## Experiment definitions

- Adds explicit experiment scope, status, primary metric, secondary metrics, expected allocation and minimum sample configuration.
- Keeps the existing three experiments and their stable session assignments.
- Makes experiment event labels human-readable in the Admin UI.

## Database and privacy

- Adds `ExperimentSessionEvent` with experiment ID, hashed session reference, variant, event and timestamp.
- Adds a composite primary key that prevents duplicate events for the same experiment/session/event combination.
- Adds indexes for experiment-result queries and retention cleanup.
- Deduplicated experiment rows are intended to be retained for up to about 31 days.
- The new experiment-session model does not store a visitor name, email, raw IP address, city or precise location.
- Adds `TrafficPageEvent` for bounded page-history analytics with indexes for time, session, country, device and path queries.
- Page-activity rows are intended to expire after about 31 days; their raw IP field is intended to be cleared after about 24 hours.
- Updates Privacy & GDPR and Cookie Policy content for both experiment measurement and retained traffic analytics.

## Compatibility

- Adds Prisma migration `20260906145500_experiment_session_events`.
- Adds Prisma migration `20260906154500_traffic_page_activity`.
- Both migrations are additive and do not rewrite or delete existing experiment or traffic aggregates.
- Existing variant and traffic-session cookies remain compatible.
