# v1.2.15 - Store product workflow

## Product creation

- Adds an explicit **Free download / Paid product** choice in the Store product editor.
- Free products always save with a zero price and do not require Creem Product ID or Lemon Squeezy Variant ID.
- Paid products keep provider configuration separate from the price field.

## Provider API workflow

- Creem products can be created automatically through the configured Creem API when a paid product is published and no existing Creem product is linked.
- The returned `prod_...` ID is stored automatically in the Necrotix Lab product.
- Existing Creem products can be loaded from the provider API and selected directly in the CMS.
- Lemon Squeezy products and variants are loaded through the Lemon Squeezy API and shown in a CMS picker, removing the need to manually find and copy Variant IDs.
- Manual provider IDs remain available only under an Advanced section.

## Local private Store storage

- Digital Store files now use private server filesystem storage by default, so Cloudflare R2 is no longer required for new products.
- The default location is `<project>/storage/store-private`, which is outside `public/` and ignored by Git.
- `STORE_PRIVATE_STORAGE_PATH` can point to an absolute persistent server directory without changing Store code.
- Uploaded files are created with private filesystem permissions and remain inaccessible through a direct public URL.
- Downloads still pass through the existing Store download-grant route, which checks paid/free access, revocation, expiry and download limits before returning file bytes.
- Existing R2-backed files remain readable/deletable as a compatibility fallback when R2 is still configured.
- Cloudflare R2 remains available as an optional migration/storage backend rather than a Store requirement.

## Media and form recovery

- Store cover images now use the existing Media Library picker.
- Previously uploaded images can be selected instead of being uploaded again.
- The Store product form no longer uses the browser/server-action auto-reset path.
- Validation errors keep all entered form values in place.
- A selected local digital file remains selected after a validation error instead of disappearing.
- Store product forms now use the existing local draft/reload protection.
- Cover image, Free/Paid mode, provider selection and provider IDs participate in draft restoration.

## Compatibility

- No Prisma migration is required for this release.
- Existing products remain compatible: a product with a zero stored price opens in Free mode; paid products retain their current provider mapping.
- Existing R2 product objects continue to work through the storage fallback when the local copy is not present.
- Creem and Lemon Squeezy checkout/webhook behavior from v1.2.14 is unchanged.
