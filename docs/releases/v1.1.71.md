# v1.1.71 - Experience Visual Restoration

## Journey timeline

- Restores the original visual language of the `/experience` Journey timeline after the v1.1.70 CMS conversion.
- Brings back year-based grouping with sticky year markers.
- Restores the animated scroll-progress timeline line from the original Experience page.
- Restores the lightweight timeline entries instead of the large numbered card layout introduced in v1.1.70.
- Restores company-logo reveal on timeline item hover for desktop layouts.
- Restores the original compact date badge, description, responsibility bullets and skill chips.
- Keeps the v1.1.70 admin visibility settings connected to timeline responsibilities and skills.

## Compact experience navigation

- Replaces the oversized Education, Journey and Experience cards with compact pill-style controls inspired by the original page.
- Keeps the active view description visible above the controls instead of repeating long descriptions inside large cards.
- Reduces vertical spacing around the selector so the Experience content starts sooner.
- Keeps disabled-view behavior and CMS-provided labels/descriptions intact.

## Partners & Sponsors showcase

- Redesigns the former Selected Experience logo area as a compact Partners & Sponsors showcase.
- Uses one clean horizontal logo strip instead of two oversized rows.
- Normalizes logo sizing and contrast for a more consistent partner wall appearance.
- Reduces empty space and section height while keeping the scrolling showcase interaction.
- Migrates the legacy default `Selected experience` title to `Partners & Sponsors` without overwriting custom marquee titles.

## CMS compatibility

- Keeps the customizable Experience admin page introduced in v1.1.70.
- Keeps Education, Journey and Experience tab visibility controls.
- Keeps the existing hero, marquee, highlights, category and card-detail controls.
- No Experience configuration is removed or reset by this release.

## Updater readiness

- Bumps Portfolio from `1.1.70` to `1.1.71` so the Admin Dashboard updater detects the visual restoration after merge into `main`.
- No Prisma migration is required.
- No dependency changes are required.
